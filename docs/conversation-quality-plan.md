### The general mechanisms (not the instances)

1. **The model obeys the last thing it reads, and the note is long.** The per-turn note is ~250 words of conditionals ("If they gave ANY detail… If they asked… If they answered… Only if…") and ends with `REQUIRED ACTION: ASK_X / <60-word ASK_AGAIN text> / DO NOT ASK ABOUT: …`. gpt-realtime-mini does the ask. Memory already recorded this ("per-turn notes beat the system prompt; the last line wins").
2. **The backend never knows what the caller said when it plans the reply.** The note is built on `committed`, before the transcript. Everything about "answer them first" is therefore conditional prose the model must apply to audio it heard. The transcript is in fact known ~400 ms before the model speaks, and always known by the time tool results go back. Nothing uses that.
3. **Phantom tool calls.** CALL STATE shows the raw caller-ID digits; the model copies them into `update_call_information` on non-detail turns. Each costs a round trip plus a filler.
4. **Form-like phrasing.** The asks are canonical-question prose ("Ask what vehicle it is (make and model, or at least the type)"); the model renders them as "Could you tell me what kind of vehicle it is?". The prompt's own sample sentences get copied verbatim (memory), so samples must *be* the voice we want. The NO PLEASANTRIES rule bans the one-word acks a person uses ("Sure", "Okay"), so replies start cold.
5. **Dead air at the worst moments.** 1.5–2.5 s of silence before the greeting (session connect); the filler timer starts only after the state op; fillers are context-blind ("Mm-hm." after a question).
6. **Nothing measures human-ness.** The eval scores fields, priority, repetition and guardrails; a reply that ignores the caller passes unless a scenario's `mention` regex happens to catch it. There are no scenarios for meta-questions, complaints, or a caller cut off mid-sentence.

## Design principles for the rewrite

- **The note knows the caller's words.** Whenever the transcript is known before the reply (≈ every turn by ~450 ms) or at tool-results time (always), the note quotes it and names what it is (question / complaint / line check / small talk / unfinished / detail). The directive is specific and LAST: `THE CALLER JUST SAID: "…" — that's a question. Answer it in one sentence, then ask where the car is.`
- **Short notes.** Target ≤ 90 words. Rules the model must apply live go in the note's last two lines; everything else goes to the cached system prompt.
- **No tool when there is no detail.** On a re-request for a non-detail turn, `tool_choice: 'none'`. Hide the raw caller-ID digits from CALL STATE ("the number they're calling from, not confirmed yet").
- **Backend still decides the next question; it now also supplies the words.** Each ask carries one natural suggested phrasing, varied by attempt (first / again / last try), e.g. ASK_LOCATION: "Where are you right now?" → "Can you give me the nearest exit, a cross street, or a business you can see?" → "Last thing I need before I pass this on: any landmark near you?".
- **A person acknowledges, then asks.** Allow one-word acks ("Okay.", "Got it.", "Alright.", "Sure."); keep banning the wordy thanks and recaps. Mirror the caller's word once ("A Civic, got it.").
- **Fixed lines stay fixed, but read like speech.** Read-back keeps every detail and the digit-by-digit number, but is phrased as a person would say it. Goodbye and ready answers rewritten in the same voice. Guardrails unchanged.
- **Verify on what ships**: unit tests → `realtime:check` (20 s) → new `conversation` eval group → model A/B → one real call by the user.

### WS-C — The gateway knows what the caller said (structural fix)
Owner files: `apps/api/src/integrations/telephony/twilio/realtime-voice.gateway.ts`, `realtime-voice.gateway.test.ts`, new `apps/api/src/integrations/realtime/caller-words.ts` + `caller-words.test.ts`, `apps/api/src/call-session/trace-format.ts` (print the new reason) if needed.

Order: detail cues (digits, street/exit/mile marker/highway, vehicle makes and types, tow/jump/flat/lockout/won't start/dead, "my name is", a yes/no answer to a pending question) → detail; `isBackchannel` → backchannel; `isPresenceCheck` → line_check; `isAskingForTime` → asking_for_time; complaint list (cut me off, not listening, asked you something, already told you, keep asking, you're not answering) → complaint; small-talk list (how are you / how's it going / weather-type questions) → small_talk; `?` or wh-/aux-inversion → question; ends without `.?!` with a function-word last token (to, the, a, an, if, and, but, so, we, you, try, that, …) or a trailing comma → unfinished; else unknown.
- Session fields: `turnKey` (the current turn's item id, set in `callerTurn()` after `expectLine`), `pinned: { state, options, turn }` (what the pinned note was built from, so it can be re-pinned with the words), `lastRequested` (set in `numbered()`, the choke point for every request; a request with one-off `instructions`, i.e. read-back / goodbye / fallback / silence check, is never replaced).
- Zero-cost path in `startTurn`'s `.then()`: if the transcript is already in `session.callerText` for `turnKey`, build the first note with `callerJustSaid` and use `toolChoice: 'none'` when the kind needs a reply; record `session.pinned`.
- The hook, `wordsKnown(session, text)`, called from `resolveLine` for the current turn's line (`line.turn === session.callerTurn`), with `deferred = session.deferredTurns.includes(key)` captured **before** the existing `answerDeferred` call (it can reach `startTurn` synchronously). Guards, all read-only, in order: closed/ending; `toolsRunning` (step below carries the words); `hold` or `callerSpeaking`; deferred (the overlap path already quotes the words); `replanPending !== null`; `turnEndedAt === null` (first non-synthetic audio already sent, the predicate that also drives the filler and latency); `pinned?.turn !== callerTurn` (closes the window before the state op resolves); `lastRequested?.instructions`. Do not re-arm the filler (it is armed for the turn and still fires at 1.1 s). A superseded response is dropped in `onResponseStarted` before it reaches `session.asks`; the backend counts asks once per action per caller turn, so no double count.
- Wrapper sequencing (no change to `openai-realtime-conversation.ts`): if `response.created` has not arrived, the cancel is a no-op and the new request queues behind it; the gateway cancels the first when it starts and the wrapper flushes ours on `response.done`.
